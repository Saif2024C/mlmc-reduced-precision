Performance Summary for scalar l = 0

Scalar Lookback, l=0, serial, N=4.19M
(perf and Advisor both at N=4.19M)

NOTE ON KERNEL SCOPE: this is a PURE Lookback kernel. The shipped l=0 branch
of nested_scalar_milstein_fp16_avx512.cpp serves both scalar payoffs from one
code path and computes the Asian integral Af unconditionally, discarding it
when option=2 (there is no `if (opt == 2)` guard, unlike the basket file where
European genuinely skips the Asian work). The benchmark strips Af, so these
numbers are the cost of the Lookback KERNEL, not of the level-0 estimator call.

Runtime / perf
--------------
fp32:
- Time/path: 8.93 ns
- Instructions retired: 0.691 G
- IPC: ~1.67
- L1 loads: 201 M
- L1 miss rate: 0.02%
- L2 misses: 45.7 K

fp16 + Kahan:
- Time/path: 7.43 ns (1.21x faster)
- Instructions retired: 0.419 G (1.65x fewer)
- IPC: ~1.22 (spans 1.08-1.22)
- L1 loads: 88.0 M (2.3x fewer)
- L1 miss rate: 0.03%
- L2 misses: 45.4 K

Instructions are deterministic, cycles vary. Quoted a median.

Correctness: chk = 17.660799 (fp32) vs 17.660887 (fp16), agreeing to 6
significant figures -- both precisions price the same option.

SIMD summary
------------
Different counters - not directly comparable:
fp32 = fp_arith_inst_retired.*  (packed single)
fp16 = fp_arith_inst_retired2.* (packed half)

fp32:
- 27.5M x 512-bit packed single (16 floats/instr)
- 76.0M x 256-bit packed single (8 floats/instr)
- 0 packed half

fp16:
- 6.6M x 512-bit packed half (32 halfs/instr)
- 22.3M x 256-bit packed half (16 halfs/instr)
- 2.6M x 512-bit packed single  <-- fp32 work left in the fp16 kernel
- 47.2M x 256-bit packed single <-- ditto

In element-ops: fp32 1.05 G, fp16 0.86 G (0.44 G half + 0.42 G single)
=> 1.65x fewer instructions, but the fp16 kernel is only about half fp16:
   63% of its vector INSTRUCTIONS are single precision (49.8M vs 28.9M), and
   49% of its element-ops (0.42 G vs 0.44 G). Instructions and element-ops
   give different fractions because a single-precision instruction carries
   half the elements of a half-precision one at the same register width.

THE HEADLINE RESULT FOR THIS KERNEL: the "fp16" Lookback kernel retires MORE
fp32 vector instructions (49.8M) than fp16 ones (28.9M). Basket European's
fp16 kernel retires exactly ZERO packed-single.

Cause: loguniform16_fp32 has no fp16 spline. The log-uniform L = log U driving
the exact Brownian-bridge minimum is drawn in fp32 and narrowed (opt::narrow16),
verbatim from the production kernel, and minbr16's sqrt chain hangs off it.
That fp32 work is irreducible without an fp16 log-uniform transform.

Clock frequency
---------------
Per-pass perf readings (serial, unpinned)

fp32:
- 1.653
- 1.670
- 1.664 GHz
Median: 1.664 GHz

fp16:
- 1.638
- 1.607
- 1.602 GHz
Median: 1.607 GHz

Overall observed range:
- 1.60-1.67 GHz
(~+/-2% variation)
No systematic frequency advantage for fp16.

Interpretation:
- Both kernels operate in the same AVX-512 downclock regime.
- Speedup is not explained by clock frequency (fp16 runs at a slightly LOWER
  clock than fp32 and is still faster).
- This kernel downclocks much harder than basket European (~1.6 GHz vs
  ~2.7 GHz). The sqrt in minbr32/minbr16 is the suspect -- heavier AVX-512
  execution-port pressure -- but this has not been isolated.

Advisor caveats
---------------
Carried over from the basket analysis; expected to apply here too, confirm
against the HTMLs:

1. Advisor labels fp16 intrinsic loops "Scalar". This is wrong - the kernel is
   __m256h intrinsics throughout, and perf shows 28.9M packed-half retired,
   zero scalar-half. Advisor's classifier does not recognise AVX-512 FP16.
   Cite perf counters, not Advisor, for vectorisation claims.

2. No fp16 roofline roof exists - all compute roofs are SP/DP (+ BF16 AMX this
   kernel never touches). Headroom quoted is against a SINGLE-precision
   ceiling. A true fp16 roof would sit ~2x higher, so any "% of peak" figure
   overstates it by roughly that factor.

Overall interpretation
----------------------
Main performance evidence:
- 1.21x lower runtime.
- 1.65x fewer retired instructions.
- 2.3x fewer L1 loads.
- Similar operating frequency (fp16 marginally lower).
- Very low L1 miss rates (0.02-0.03%) -- compute-bound, not memory-bound.
- Very small L2 miss counts.
- LOWER IPC than fp32.

fp16 wins by doing less work per path, not by running the pipeline harder.
Do not "optimise" this kernel for higher IPC.

Comparison with basket European -- the reason this kernel was profiled:

                        basket European    scalar Lookback
  fp32 time/path            27.8 ns            8.93 ns
  fp16 time/path            11.8 ns            7.43 ns
  speedup                   2.2x               1.21x
  instructions              2.4x fewer         1.65x fewer
  L1 loads                  5.2x fewer         2.3x fewer
  fp32 instrs in fp16 kernel  0                49.8M (63% of vector work)
  clock                     ~2.7 GHz           ~1.6 GHz

The fp16 advantage nearly halves on Lookback. This is the useful finding: fp16
does not deliver a uniform speedup across payoffs, and the size of the win is
governed by how much of the kernel can actually run in fp16. Basket European
converts essentially all of its arithmetic; Lookback cannot, because the
Brownian-bridge minimum needs a log-uniform that has no fp16 transform.

Implication: an fp16 superdyadic spline for log U, analogous to norminv_fp16,
is the single change most likely to move Lookback's number toward basket
European's. Not attempted here.

Still outstanding
-----------------
- Loop unrolling effects: not yet measured.
- The harder downclock (~1.6 GHz vs basket's ~2.7 GHz) is unexplained; the
  sqrt in minbr is the suspect but this was not isolated.
