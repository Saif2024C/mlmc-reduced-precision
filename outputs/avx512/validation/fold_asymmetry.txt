### RESOLVED 2026-08-03: Giles updated my_mm512.h
################################################################

The fold predicate on line 272 changed:

    -  __mmask32 m = _mm512_cmplt_epu16_mask(two_to_15, i);   // strict, skips i=32768
    +  __mmask32 m = _mm512_cmpge_epu16_mask(i, two_to_15);   // i >= 2^15, folds it

This is the non-strict comparison the probe above predicted, and it now
matches the scalar normal_dyadic2's  m = (i >= (1<<15)).

Verified after swapping the header in (coupling_test.cpp Test 4, mimic):
    asymmetric pairs = 0 of 32768        (was 1)
coupling_test.cpp's tolerance was tightened from  nasym <= 1  to  nasym == 0
so a regression cannot pass silently.

Estimator impact: none measurable, as section 4 above predicted. beta over
all 16 runs (scalar/basket x 4 modes x 2 options) is unchanged vs the
pre-swap values recorded in CLAUDE.md -- adaptive 2.219/1.913 (scalar),
1.961/2.151 (basket). One input in 65536 does not move a regression.

Accuracy note, unchanged by the fix: at i=32768 the OLD behaviour was the
more accurate one (err 1.9e-05 vs 3.7e-04), because the true value there is
below fp16's 3.5e-4 resolution near zero. The fix buys exact symmetry, not
accuracy, and gives up 19x at that single input. Both errors are far below
the 5.4e-3 bulk spline error, so neither matters to the estimator.
